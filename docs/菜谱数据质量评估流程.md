# 菜谱数据质量评估流程

## 范围与运行

从仓库根目录运行只读脚本（Python 3.12+，仅用标准库）：

```powershell
python scripts/evaluate_recipes.py --report-dir recipe-quality-report
```

默认读取 `data/seed/recipes.json` 和 `apps/web/public/data/recipes_merged.json`。也可显式指定文件：

```powershell
python scripts/evaluate_recipes.py apps/web/public/data/recipes_howtocook.json --report-dir recipe-quality-report
```

脚本只检查 JSON 文件，不连接数据库，不写入菜谱，也不创建向量索引。`--report-dir` 下生成：

- `summary.json`：文件数、问题数量、能力候选数量。
- `items.jsonl`：每条菜谱的问题、能力候选、来源引用。
- `manual_review.csv`：确定性分层抽样清单，可用 `--sample-size` 和 `--seed` 调整。

重复运行相同输入、样本数和种子应得到同一份结果。输出目录中已有的同名报告会被覆盖；需要保存历次结果时使用带日期的独立目录。

## 评估顺序

1. **冻结输入**：记录源文件版本、取得日期、许可依据和文件摘要。合并文件是派生数据，审核来源时回到原始文件和原始页面。
2. **全量自动检查**：运行脚本，逐条修复无名称、无食材、无步骤、无用量、同名候选等问题。`*_candidate` 只表示字段满足最低条件，不代表内容准确或已获授权。
3. **人工来源审核**：按每个来源确认许可是否覆盖存储、嵌入、App 展示、图片和做法；保留证据。`RIGHTS_UNVERIFIED` 不能靠抽样或仅有链接消除。
4. **人工内容抽检**：使用 `manual_review.csv`，对照原始来源核对食材、步骤顺序、过敏原、单位和关键烹饪条件。样本覆盖有步骤、无步骤、种子及重名候选；对安全相关冲突和可疑来源扩大到全部受影响记录。
5. **能力分级与发布门禁**：分别标记“可发现”“可回答做法”“可计算用量”。只有来源审核通过、字段与内容满足对应能力要求的记录才进入正式索引。未知过敏原不能当作无过敏原；未知用量不能用于库存扣减或采购量计算。
6. **检索与回答评测**：在批准的数据上建立索引后，另用标注问题评估 Recall@5、Hit@5、错误推荐、引用和延迟；数据质量通过不意味着检索效果合格。

## 问题代码与局限

- `NAME_MISSING`、`INGREDIENTS_MISSING`、`INGREDIENT_INVALID`、`STEPS_INVALID`、`ALLERGENS_INVALID`：结构或类型问题，须先修复。
- `STEPS_MISSING`：可作为发现候选，不能当作完整做法。
- `QUANTITY_UNKNOWN`、`QUANTITY_INVALID_OR_MISSING`、`SERVINGS_INVALID_OR_MISSING`、`DURATION_INVALID_OR_MISSING`、`NUTRITION_OR_COST_INVALID`：需要修复或保持对应能力不可用。
- `SOURCE_MISSING`、`SOURCE_URL_INVALID`、`SOURCE_OR_LICENSE_MISSING`、`RIGHTS_UNVERIFIED`：需要来源和权利审核。脚本不会自动授予发布许可。
- `POSSIBLE_DUPLICATE_NAME`：名称规范化后相同；可能是同一道菜，也可能是不同做法，不能自动合并。

当前 V1 合并 JSON 的 `stuff` 是自由文本，脚本不从中猜测数量；`bv` 是来源线索，不是授权凭证。种子数据的 `license_note` 是文件中的声明，不等于脚本已验证权属。图片缺失不阻止纯文本菜谱；如产品要求图片，应另设图片能力与授权门禁。

30 条抽样用于**发现内容问题**，不构成全库准确率的统计保证。上线前的来源审核、过敏原关键规则和高风险异常不能只靠这 30 条样本。
