# 助手工具封装与重建说明

## 当前状态

旧 Agent 的模型决策、意图路由、工具循环和旧配餐实现已退役。当前没有运行中的新 Agent，也没有新配餐 Workflow。

本轮交付的是六个可独立调用的工具。会话历史、鉴权、任务入队基础设施、worker 租约和采购确认机制保留。App 助手显示“助手正在重建，暂不可用”，暂停发消息、续接和生成菜单。库存、人员和采购业务继续使用原有接口。

新建 V2 对话任务经过鉴权后返回 HTTP 503，`detail.code=AGENT_REBUILDING`，不会入队。内部 `enqueue_turn` 保留基础设施能力，供后续实现使用，不作为本轮外部执行入口。worker 领取遗留任务后以 `AGENT_REBUILDING` 结束；取消、权限撤销和租约检查继续生效。历史记录和已有待确认动作不删除。

## 代码分层

- `apps/api/app/tools/contracts.py`：工具声明、统一结果、参数和执行边界。
- `apps/api/app/tools/assistant.py`：六个工具、可信上下文与业务查询。
- `apps/api/app/cli/call_assistant_tool.py`：本地开发调用入口。
- `apps/api/app/services/research_retrieval.py`：研发混合检索和按批次、版本回源详情。
- `apps/api/app/agent/runtime.py`：保留给 worker 的基础任务契约，不含 Agent 决策。
- `apps/api/app/services/v2_runtime.py`：权限、会话、采购草稿和确认服务。

工具依赖业务服务和数据库，不依赖旧 Agent 的状态，不创建新的 StateGraph，不调用生成模型。普通工具可直接使用 Python 函数；后续配餐工具再封装固定 Workflow。

## 六个工具

| 名称 | 参数 | 行为 |
| --- | --- | --- |
| `search_recipes` | `query`；`top_k=5`，范围 1～20 | 固定调用研发混合检索，返回父菜谱、片段、来源、分数和版本 |
| `get_recipe_detail` | `document_id`、`content_version` | 检查固定批次及内容版本，读取完整父菜谱，不加载 BGE |
| `get_inventory_summary` | `search=""`、`offset=0`、`limit=50` | 当前家庭有效已确认库存，支持名称和食材别名查询 |
| `get_member_profiles` | `member_ids=null`、`as_of=null`、分页参数 | 当前家庭人员与原始限制，返回查询日期内有效事件 |
| `get_procurement_list` | `search=""`、`status="pending"`、分页参数 | 查询采购清单；`status=null` 查询全部状态 |
| `prepare_procurement_action` | `name`、`quantity_status`、`quantity`、`unit`、`note` | 创建单项待确认草稿，不直接增加采购条目 |

列表统一返回 `items / total / offset / limit`，每页最多 100 条。`total` 是筛选后的总数，不是当前页长度；空页可能是偏移超出范围，不一定代表全库没有记录。

人员默认日期使用 Asia/Shanghai；事件起止日都包含当天。无记录不解释为无过敏，原始文本不自动分类为过敏，家庭成员清单不代表本次用餐人员选择。非法事件日期返回 `partial` 和告警，需要人工核对。

库存只返回 `active` 记录，不将视觉观察当作已确认库存。未知数量仍为 `quantity_status=unknown, quantity=null, unit=null`，过期日期不自动改变库存事实状态。

采购状态支持 `pending / purchased / archived / null`。已知数量要求数量和单位，数值精度沿用业务契约；未知数量不允许额外填写数量、单位。

准备采购时，已知名称或别名唯一匹配目录才关联食材；其他名称保留原文、标注未关联，不自动创建食材。准备结果中的 `pending_action` 包括 ID、payload、payload_hash、version 和 expires_at。确认继续使用现有 HTTP `/api/v2/actions/{action_id}/confirm` 或 reject 接口，身份、CSRF、版本、过期和幂等规则保持原样。模型没有确认工具。

## 返回与错误

所有工具返回：

```json
{
  "status": "ok",
  "data": {},
  "warnings": [],
  "evidence_ids": [],
  "data_versions": {},
  "error_code": null
}
```

- `ok`：操作成功且有结果。
- `no_result`：查询成功，本页没有候选。
- `partial`：有可用信息，但存在明确的不完整信息，例如人员事件日期异常。
- `unavailable`：配置、依赖、数据库或时间预算使工具暂不可用。
- `error`：参数、权限、版本一致性或其他执行错误。

常见错误包括 `UNKNOWN_TOOL`、`INVALID_ARGUMENTS`、`PROFILE_NOT_FOUND`、`DATABASE_UNAVAILABLE`、`TOOL_TIMEOUT`。菜谱沿用 `index_config / model_config / embedding_failed / database_failed / evidence_mismatch`，不会用空列表掩盖失败。

来源 ID 与版本用于定位证据，不证明内容已获得正式发布资格。搜索分数不是正确概率，搜索不执行饮食安全过滤。

## 可信上下文与运行资源

身份、家庭、数据库 session factory、模型目录和研发索引批次通过 `ToolContext` 注入，不出现在模型可填写的参数里。每个工具实际执行前检查当前家庭成员关系。新工具没有公开通用 HTTP 执行接口；CLI 中的用户 ID 仅为本地开发可信身份，不是客户端认证方案。

一个进程应复用同一个工具集实例及检索器，避免重复加载 BGE。搜索延迟加载模型；详情、库存、人员和采购不加载模型。同步模型与 SQL 工作在执行线程中运行，不阻塞异步执行器；搜索预算 120 秒，其余工具 10 秒。CLI 数据库连接超时为 5 秒，工具查询/采购草稿事务及研发检索 SQL 设置 10 秒语句超时，推理期间不持有数据库事务。

异步超时不能强制停止已运行的 Python 工作线程。搜索超时后的计算可能继续，采购准备也可能已经产生待确认记录；不会因此直接执行采购确认，不应盲目自动重试准备操作。本轮不提供采购草稿的请求级去重接口，确认仍按既有动作 ID 和幂等键防重复写入。

## 本地使用

在仓库根目录按现有命令安装依赖；从 `apps/api/` 运行下面命令。模型推理还需要现有 torch、transformers 和本地 BGE 文件。

本地 `.env` 配置：

```dotenv
RESEARCH_RETRIEVAL_BATCH_ID=286bfcc1-52d1-451c-b126-62295cc22259
RESEARCH_EMBEDDING_MODEL_DIR=models/bge-small-zh-v1.5
```

示例批次来自此前研发索引，运行时仍会检查实际状态；不自动挑选最新批次。未配置批次时只有菜谱工具不可用，其他工具照常工作。研发批次保持未发布，不修改 `production_publishable` 或来源批准状态。

准备一个 UTF-8 参数文件，例如 `search-arguments.json`：

```json
{"query": "番茄炒蛋怎么做？", "top_k": 5}
```

本地终端示例，身份值需替换为实际的当前家庭成员 ID：

```powershell
# 只展示模型可见的六个工具声明，不查询业务数据。
python -m app.cli.call_assistant_tool --actor-id USER_ID --household-id HOUSEHOLD_ID

# 调用菜谱搜索。
python -m app.cli.call_assistant_tool --actor-id USER_ID --household-id HOUSEHOLD_ID --tool search_recipes --arguments-file search-arguments.json
```

其他参数文件示例：

```json
{"document_id": "搜索结果中的文档ID", "content_version": "搜索结果中的64位内容摘要"}
```

```json
{"search": "番茄", "offset": 0, "limit": 50}
```

```json
{"member_ids": ["实际人员ID"], "as_of": "2026-11-14"}
```

```json
{"status": null, "offset": 0, "limit": 50}
```

```json
{"name": "紫苏叶", "quantity_status": "known", "quantity": "0.1", "unit": "kg", "note": "晚餐使用"}
```

参数包含身份、批次等未声明字段时返回 `INVALID_ARGUMENTS`。工具返回 `error` 或 `unavailable` 时 CLI 退出码为 2，其他结果为 0。CLI 准备采购会真实创建待确认草稿，应使用明确的测试参数和正确家庭；本轮验证只在独立测试库执行。

## 验证与后续边界

测试脚本覆盖参数、权限、分页、日期、采购确认及退役状态；真实 pgvector SQL 使用独立 `_test` 数据库和可控编码器替身。没有运行付费模型或输出检索效果评估结论。

之后依次建设：外层模型工具选择循环、菜谱证据回答链路、人员与库存驱动的配餐 Workflow。BM25、Rerank、查询词优化及检索评估另行安排。
