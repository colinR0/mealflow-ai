# 智慧冰箱 App · UI 视觉与交互设计规范（现代精工·深空钛灰风）

## 1. 设计概述与定位边界

### 1.1 产品定位与交付范围
* **产品名称**：用户可见名称统一使用“智慧冰箱”文字标识，不展示内部项目代号，不臆造真实家电厂商名称与品牌 Logo。
* **终端与技术形态**：面向中国大陆家庭用户的独立 Android 竖屏移动应用（基于 HBuilderX + uni-app + Vue 3 + TypeScript 构建），不含桌面端品牌管理后台。
* **核心任务优先级**：优先解决“查看家庭已确认食材、理解助手执行结果与确认操作、维护家庭共享采购清单、管理家庭成员用餐档案”四大日常高频任务，摒弃营销落地页、复杂数据仪表盘与纯装饰性大卡片。

### 1.2 真实性边界与目标态标注原则
* **严禁伪造硬件与识别状态**：当前冰箱摄像头、真实设备状态、图像采集与视觉识别尚未接入。首页冰箱示意图仅作为弱化的产品识别元素，必须紧邻标注“示意图，非实时画面”，严禁伪造识别检测框、模型置信度、设备在线状态或最后拍摄时间。
* **严格区分已知数量与数量未知**：库存记录必须由家庭确认后方可进入“已确认库存”。对于数量未知的食材，必须原样展示“数量未知”或“待核对”，严禁替换为数字 0，严禁自动估算库存缺口或临期保质期。
* **现状与目标态视觉隔离**：凡尚未开放接口或待接入的能力（如识别结果核对、手动增删改库存、采购项状态勾选与确认入库、单菜替换、家庭邀请等），必须在界面显著位置（顶部通栏警示条或虚线容器角标）明确标出“目标态 / 模拟数据 / 尚未接入”，防止评审与开发人员误认为已上线。

### 1.3 全局统一示例数据上下文
全套 UI 原型与设计稿统一采用以下虚构家庭数据，确保跨页面演示逻辑自洽：
* **当前选中家庭**：林家（支持切换家庭，切换后四栏页面数据同步隔离切换）
* **家庭用餐成员**：
  * **妈妈**：常驻成员，女；过敏项为“海鲜、花生”；长期忌口为“不吃香菜”。
  * **小林**：常驻成员，男；长期忌口为“少油少辣”；当前生效特殊情况为“肠胃不适（2026-10-14 至 2026-10-20 · 进行中 · 清淡、温热、忌生冷）”。
* **已确认库存食材**：鸡蛋（8 个，确认于 10:30）、番茄（数量未知，确认于昨日）、鲜牛奶（2 盒，确认于昨日）、牛腩（数量未知，确认于 2 天前）、西兰花（1 颗，确认于 2 天前）。

## 2. 全局视觉设计系统（风格三：现代精工 · 深空钛灰）

### 2.1 画布尺寸与安全区规格
* **标准设计画布**：Android 手机竖屏，主视觉稿基准宽度为 390 px，同时向下兼容 360 px 窄屏（验证长文本折行与防挤压）并向上适配 430 px 宽屏。
* **系统安全区预留**：顶部预留 Android 状态栏高度，底部固定四栏主导航并预留全面屏手势安全区。
* **最小触控热区**：所有可点击按钮、图标、分段开关与列表操作项的触控目标尺寸均满足 $\ge 44 \times 44\text{ px}$。

### 2.2 色彩体系（多色相语义区分）
摒弃全屏浅蓝渐变与单一蓝色系，采用深空钛灰锚点搭配多色相语义标签，且所有颜色状态均同时配备文字标签或图标，不以红/绿颜色作为唯一状态信号：

| 语义角色 | 颜色名称 | 色值参考 | 适用场景与视觉规范 |
| --- | --- | --- | --- |
| 顶栏与状态锚点 | 深空钛灰 | #18181B | 页面顶栏、当前家庭上下文导航、首页设备未接入状态锚点区 |
| 页面与容器基底 | 浅银灰 / 纯白 | #F3F4F6 / #FFFFFF | 页面底层背景使用浅银灰，列表面板使用纯白配 1 px 细边框 #E5E7EB |
| 品牌与主交互色 | 精工钴蓝 | #2563EB | 底部主导航选中态、主操作按钮、操作确认卡“确认写入”按钮 |
| 未知与目标态色 | 亮琥珀色 | #D97706 / #FEF3C7 | “数量未知 / 待核对”胶囊标签、“目标态 / 模拟数据”顶部通栏提示 |
| 过敏与错误阻断 | 克制暗红 | #DC2626 / #FEE2E2 | 医学“过敏”标签（配警告图标）、日期校验错误、网络加载失败提示 |
| 进行中与已完成 | 森林翠绿 | #16A34A / #DCFCE7 | 临时特殊情况“进行中”标签、助手任务步骤“已完成”勾选标识 |
| 次要与禁用状态 | 中性岩灰 | #6B7280 / #D1D5DB | 确认时间戳、未选中导航图标、不可发送状态的禁用按钮 |

### 2.3 字体层级与版式规范
* **去卡片套叠化**：禁止在卡片内部套叠多层圆角阴影白卡。采用通栏列表、版面分区色块与 1 px 极细分隔线（#E5E7EB）建立信息层级。
* **文字字号阶梯**（固定字号，不随视口宽度盲目放大）：
  * 页面主标题 / 顶栏标题：18 px，字重 Bold（600）
  * 模块分区标题 / 菜品名称 / 成员姓名：16 px，字重 Medium（500）
  * 列表正文 / 食材名称 / 对话气泡正文：15 px，字重 Regular（400），行高 1.5
  * 辅助说明 / 确认时间 / 来源标注：13 px，字重 Regular（400）
  * 状态胶囊标签 / 目标态角标：12 px，字重 Medium（500）
* **长文本防溢出机制**：长食材名称、长家庭名称及成员自由备注支持自然多行折行，列表行高随内容自适应扩展（基础单行高 $\ge 56\text{ px}$），严禁与右侧数量标签、状态胶囊或操作按钮发生重叠。

## 3. 全局导航与页面架构树

### 3.1 底部四栏固定主导航
底部导航固定为四栏，顺序不可变更，严禁增加第五个底部入口。选中态同时高亮图标与文字（精工钴蓝 #2563EB）：

| 顺序 | 导航名称 | 核心职责定位 | 默认首屏展示内容 |
| --- | --- | --- | --- |
| 1 | 冰箱 | 查看已确认食材、未知数量及服务状态，通往完整库存 | 冰箱概览页（默认打开首页），突出真实库存数据与未接入提示 |
| 2 | 助手 | 自然语言查询家庭食材、讨论晚餐方案、发起待确认操作 | 对话起始态、高频快捷问题胶囊、历史任务流与底部固定输入区 |
| 3 | 采购 | 集中管理家庭共享采购清单与跟进购买状态 | 待购买清单列表，顶部提供待购买、已购买、已归档三态分段切换 |
| 4 | 家庭 | 手机号登录、家庭切换隔离、管理家庭成员用餐档案 | 当前家庭摘要与成员用餐档案列表；未登录时展示手机号登录页 |

### 3.2 完整页面层级树
1. **冰箱模块**
   * 冰箱概览（一级默认首页 · 已交付现状）
   * 冰箱库存（独立二级页，从概览进入 · 已交付现状）
   * 食材详情（从库存行进入 · 目标态）
   * 识别结果核对（设备接入后的候选食材核对页 · 目标态）
2. **助手模块**
   * 对话起始态与任务流主页（一级页 · 已交付现状）
   * 操作确认卡（对话流内嵌展开 · 已交付现状）
   * 晚餐建议 / 菜谱方案详情（由对话结果进入 · 目标态）
3. **采购模块**
   * 家庭采购清单：待购买 / 已购买 / 已归档（一级页 · 已交付现状）
   * 新增或编辑采购项、行级勾选已购买（目标态）
   * 确认入库独立核对页（从已购买发起，与已购买严格分开 · 目标态）
4. **家庭模块**
   * 手机号登录 / 未加入家庭引导页（一级页状态 · 已交付现状）
   * 家庭切换与成员用餐档案列表（一级页 · 已交付现状）
   * 新增 / 编辑人员档案及特殊情况（独立二级页或全屏面板 · 已交付现状）

## 4. 四大业务板块详细 UI 设计规范

### 4.1 冰箱板块

#### （1）冰箱概览（默认一级首页）
自上而下严格按以下 6 个区块排列，不设设备控制开关或营销横幅：
1. **深空钛灰顶栏**：左侧展示应用标题“智慧冰箱”，右侧展示当前家庭切换器“林家 ▾”（未登录或无家庭时显示“未选择家庭 / 去登录”）。
2. **冰箱服务状态区（深色锚点内嵌）**：左侧放置克制的极简线条冰箱示意图并紧邻标注“示意图，非实时画面”；右侧以琥珀色醒目胶囊标注“摄像头与识别服务尚未接入”。
3. **食材概览指标卡**：悬浮于深浅交界处的双栏数据面板，左侧展示“已载入确认记录：12”，右侧展示“数量未知 / 待核对：3”（琥珀色高亮）。无法获取的临期或识别待办指标不展示或显示“—”。
4. **高频操作区**：左侧为搜索入口“搜索已载入的食材记录”，右侧或下方并列三个轻量快捷按钮：「完整库存」「助手」「采购」。
5. **已确认食材预览列表**：展示前 3 至 5 条最新确认记录（如鸡蛋 8 个、番茄 数量未知、鲜牛奶 2 盒），每行包含食材名称、数量或“数量未知”琥珀色标签、确认时间。底部提供通栏入口“查看全部库存 (12) >”。
6. **底部固定四栏主导航**。

#### （2）冰箱库存（独立二级页）
* **顶栏导航**：保留深空钛灰顶栏，左侧返回按钮，中间标题“冰箱库存”，右侧显示当前家庭“林家”。
* **范围限定搜索框**：占位提示文案明确为“搜索已载入的食材记录（共 12 条）”，向用户传达仅在已载入确认记录内筛选，不暗示全库模糊智能检索。
* **轻量分段筛选**：提供「全部 (12) | 数量未知 (3)」双栏分段控件。不展示当前数据不支持的“临期 / 过期 / 冷藏室位置”筛选；若展示类别筛选须标为目标态。
* **库存清单行**：左侧为主字号食材名称（支持多行换行）与确认时间戳，右侧展示具体数量单位（如 8 个）或琥珀色胶囊“数量未知 / 待核对”。
* **目标态操作区隔离**：页面底部以虚线置灰容器放置“手动新增 / 编辑 / 标记用完 / 丢弃”，并配角标“目标态 / 待接口支持”。

#### （3）识别结果核对页（目标态）
* **顶部目标态通栏警示**：顶栏正下方固定琥珀色通栏横幅：“目标态 / 模拟数据：摄像头与视觉识别服务尚未接入”。
* **来源画面信息**：展示线框模拟示意图（明确标注“视觉模拟画面，非真实采集”）及模拟采集时间，不绘制虚假 AI 识别框与置信度百分比。
* **候选食材逐条核对**：
  * 针对候选新增项（如“鸡蛋 · 候选新增 8 个”）：提供「确认新增」「修正」「忽略」按钮。
  * 针对已有记录更新项（如“番茄 · 数量未知”）：提供「更新记录」「忽略」按钮。
* **写入前预览栏**：底部固定面板汇总“预览写入变更：将向【林家】已确认库存写入 2 项变化”，点击主按钮「确认写入库存（目标态）」完成闭环。

### 4.2 助手板块

#### （1）对话主页与任务状态流
* **顶栏与家庭上下文**：深空钛灰顶栏展示“智慧助手”与右侧“林家 ▾”。
* **快捷问题建议区**：顶部排列 4 个轻量胶囊按钮：
  * “冰箱里还有鸡蛋吗？”
  * “把牛奶加入采购清单”
  * “用番茄和鸡蛋想一道晚餐”
  * “家里有人不吃什么？”
  * *交互约束*：点击胶囊仅将问题填入或作为用户消息发出，绝不静默改写后台共享数据。
* **面向用户的任务步骤条**：助手回复前展示轻量过程卡片（如 `✓ 查询已确认食材 (已完成)` $\rightarrow$ `✓ 生成待确认操作`），隐藏内部 Prompt、工具调用参数与模型原始日志。運行中状态提供「取消」按钮；失败或断线恢复后保留已有上下文并提供「重试 / 检查状态」，防止重复提交。
* **固定输入区**：贴合底部导航上方，适配 Android 软键盘弹出与多行文本输入；未登录、未选家庭或输入为空时，右侧发送按钮呈现清晰禁用态。

#### （2）操作确认卡（共享数据修改拦截）
当对话涉及“加入采购清单”或“保存长期饮食偏好”等共享数据写操作时，必须在对话流内展开结构化确认卡：
* **必含字段**：卡片标题“操作确认卡”、当前状态标签（待确认 / 提交中 / 已完成 / 已取消 / 已过期 / 版本冲突）、操作名称（如“加入采购清单”）、目标家庭（林家）、拟写入内容（如“鲜牛奶 · 数量未知 / 待核对”）。
* **操作按钮**：并列提供「取消」与钴蓝色主按钮「确认写入」。
* **冲突与过期防护**：若提交失败，严禁假报成功；若卡片已过期或发生他人并发修改冲突，隐藏原确认按钮，替换为「刷新并重新核对」按钮。

#### （3）晚餐建议方案页（目标态）
* **顶部目标态标注**：通栏标注“目标态 / 模拟数据：晚餐方案与单菜替换预览”。
* **家庭档案有效约束置顶卡**：展示本次用餐成员（小林、妈妈），并排列三类不同语义色彩的约束标签：
  * 暗红警告标签：`⚠️ 妈妈：海鲜过敏`
  * 中性灰标签：`忌口：不吃香菜、少油少辣`
  * 翠绿进行中标签：`进行中：小林 肠胃不适（需清淡温热）`
* **菜品卡片与库存依据**：
  * 示例菜品 1（番茄滑蛋 · 用时 15 分钟）：明确标注“依据已确认库存：鸡蛋 (8 个)、番茄 (数量未知/需核实)”，底部提供「替换此菜」按钮（替换单菜时保留其他菜品与家庭约束）。
  * 示例菜品 2（山药瘦肉粥 · 用时 35 分钟）：明确标注“缺少食材：铁棍山药、猪瘦肉”，底部提供「预览并加入采购清单（需确认）」按钮。

### 4.3 采购板块

#### （1）家庭采购清单（一级页）
* **顶栏与三态分段导航**：深空钛灰顶栏展示“家庭采购清单”与“林家 ▾”；下方紧接白色背景分段控件：「待购买 (3) | 已购买 (2) | 已归档 (5)」，无数据时不虚构数字。
* **紧凑清单列表**：每行展示食材名称（如鲜牛奶、铁棍山药、猪瘦肉）、数量状态（已知数量 `2 根` 或琥珀色胶囊 `数量未知`）、来源标注（如“来源：助手确认”）以及右侧当前状态文字“待购买”。
* **目标态操作隔离区**：页面下方使用虚线容器承载「+ 新增采购项」与「勾选已购买 / 撤销」操作，配醒目角标“目标态 / 待开放接口”，且行级操作预留「撤销」入口以防误触。

#### （2）确认入库独立流程页（目标态）
* **核心业务规则**：“已购买”仅代表采购状态，不等于食材已进入冰箱库存。必须从“已购买”分区独立发起「确认入库」流程。
* **顶部目标态警示**：通栏标注“目标态 / 模拟数据：已购买不等于已入库，需独立核对写入”。
* **逐项核对表单**：
  * 针对“鲜牛奶（原购买数量：2 盒）”：提供实际入库数量数字输入框（默认填入 2）与单位显示（盒）。
  * 针对“生姜（原购买数量：待确认）”：支持直接开启琥珀色开关标记为“数量未知 / 待核对”。
* **写入预览与提交**：底部固定提示“写入预览：将向【林家】已确认库存新增 2 条记录”，点击「确认入库（目标态）」成功后，原采购项状态变更为“已入库”；若失败则保留原状态并允许重试。

### 4.4 家庭板块

#### （1）家庭与人员档案列表页（一级页）
* **严格模块边界**：家庭页仅管理账号、当前家庭切换与成员用餐档案，**严禁放入“我的冰箱”、冰箱库存列表、设备在线状态或食材预览**。
* **当前家庭切换栏**：深空钛灰顶栏展示“家庭与人员档案”及右侧家庭切换器“当前家庭：林家 ▾”。
* **用餐人员档案卡片列表**：标题栏右侧提供「+ 新增人员」按钮。每张成员卡片展示：
  * **基础头部**：姓名（妈妈 / 小林）+ 身份与性别胶囊（`常驻成员 | 女` / `常驻成员 | 男`）。未填写字段不展示空白标签。
  * **过敏与忌口行**：医学过敏使用暗红底色配警告图标 `⚠️ 过敏：海鲜、花生`；饮食偏好使用中性灰胶囊 `忌口：不吃香菜`。
  * **生效中的特殊情况**：使用翠绿圆点与浅绿底色展示 `● 特殊情况进行中：肠胃不适 (10/14 - 10/20 · 清淡温热)`。已过期的历史特殊情况不作为当前约束在卡片高亮。
  * **行级操作**：卡片右下角提供独立的「编辑」与「删除」文字按钮（点击删除必须弹出二次确认弹窗）。
* **底部账户区**：放置虚线标注的「邀请家庭成员（目标态 / 待确认）」入口，以及最底部的「退出登录」按钮。

#### （2）人员档案与特殊情况编辑页（独立二级页）
顶部固定深空钛灰导航栏（左侧「取消」、中间「编辑人员档案 · 小林」、右侧钴蓝色「保存」），页面主体分为三组卡片表单：
1. **基础信息组**：姓名（必填输入框）、身份选择（常驻成员 / 访客）、性别（可选：男 / 女 / 保密）、自由描述与备注（由家庭自行填写，系统不作健康推断）。
2. **过敏与忌口组**：
   * 独立分行管理“⚠️ 过敏”与“忌口”，提供「+ 添加限制」入口。
   * 严禁将“不吃香菜”等自然语言偏好与“海鲜过敏”等医学过敏混为一类。
   * 保存整份档案时若遇并发修改冲突，弹出提示引导用户刷新后重试，不静默覆盖他人修改。
3. **临时特殊情况组**：
   * **情况类型选择**：支持感冒、例假、肠胃不适、康复期、自定义情况（仅作家庭备忘记录，不用于医疗诊断）。
   * **起止日期与状态校验**：提供开始日期与结束日期选择器，自动计算并显示「未开始 / 进行中 / 已结束」状态标签。当结束日期早于开始日期时，立即在字段下方以暗红色文字就地提示“结束日期不得早于开始日期”，并阻断保存按钮。
   * **家庭自选饮食标签**：提供「清淡」「温热」「忌生冷」「少渣」等标签供家庭自行勾选确认，系统绝不根据病症名称自动生成医疗建议或营养疗效承诺。

#### （3）未登录与未加入家庭状态页
* **手机号登录态**：仅支持中国大陆 11 位手机号 + 密码登录，提供清晰的加载中、密码错误就地提示与重试能力；**不设计邮箱登录或第三方社交账号入口**。
* **已登录但未加入家庭态**：展示明确空态说明“当前账号尚未加入任何家庭”，提供「刷新家庭列表」按钮与「通过家庭邀请加入（目标态 / 待确认）」说明，严禁展示任何残留或虚构家庭数据。

## 5. 全局状态与反馈设计规范矩阵

在实际前端页面开发与 UI 交付中，所有涉及数据读写的界面均须覆盖以下对应状态：

| 状态类型 | 视觉呈现与文案规范 | 交互约束与恢复路径 |
| --- | --- | --- |
| 未登录状态 | 家庭页直接显示 11 位手机号登录表单；冰箱、助手、采购三栏显示受限空态说明 | 提供跳转至家庭页登录的主按钮；严禁展示旧会话缓存的家庭数据 |
| 未选择 / 未加入家庭 | 显示“未选择家庭上下文”提示图标与具体说明文案 | 提供选择已有家庭、刷新状态或查看邀请说明的下一步入口 |
| 首次空数据状态 | 用一句具体中文解释为何为空（如“林家暂无已确认的冰箱食材记录”） | 提供当前可用的真实操作入口；严禁将示例假数据伪装成真实记录 |
| 数据加载中 | 保留深空钛灰顶栏与分段结构，列表区展示银灰色轻量骨架条（Skeleton） | 避免全屏阻塞式无意义转圈；助手运行中提供明确的「取消」按钮 |
| 网络或读取错误 | 在列表区或顶部就地展示暗红色错误说明条，保留页面已有可用内容 | 必须提供可点击的「重试」按钮，点击后重新发起当前分区数据请求 |
| 数量未知状态 | 统一使用琥珀色胶囊标签原样展示“数量未知”或“数量未知 / 待核对” | 严禁替换为数字 0，严禁在助手或采购模块中自动计算食材缺口数量 |
| 设备未接入状态 | 在冰箱概览页顶栏下方固定展示“摄像头与识别服务尚未接入” | 严禁使用虚假在线绿点、旧抓拍画面或 AI 检测框冒充实时状态 |
| 操作待确认状态 | 助手内展开浅蓝底色结构化“操作确认卡”，列明目标家庭与拟写入内容 | 用户点击「确认写入」前，界面文案绝不得声称“已成功添加/修改” |
| 操作失败 / 版本冲突 | 确认卡或编辑页就地显示暗红色失败/冲突原因，保留用户已输入内容 | 隐藏失效的旧确认按钮，提供「重试」或「刷新并重新核对」按钮 |
| 目标态模拟页面 | 在画面顶部固定琥珀色通栏或在组件外围加虚线框，标注“目标态 / 模拟数据” | 确保评审者在脱离外部说明文档时，仅看画面即可一眼识别未上线功能 |

## 6. 原型交互走查路径与交付验收清单

### 6.1 核心交互走查路径
1. **现状链路一（库存查询闭环）**：打开 App 默认进入「冰箱概览」（查看林家 12 条已载入记录与 3 条数量未知、设备未接入提示）$\rightarrow$ 点击“查看全部库存”进入「冰箱库存二级页」$\rightarrow$ 切换“数量未知”筛选或搜索“番茄”$\rightarrow$ 通过底部导航切换至「助手」或「采购」。
2. **现状链路二（助手确认卡拦截闭环）**：进入「助手」点击快捷问题“把牛奶加入采购清单”$\rightarrow$ 查看“查询已确认食材”运行步骤与回答结果 $\rightarrow$ 展开「操作确认卡（状态：待确认）」核对目标家庭“林家”与拟写入项“鲜牛奶（数量未知）”$\rightarrow$ 点击「确认写入」完成提交。
3. **现状链路三（家庭档案与特殊情况闭环）**：进入「家庭」查看林家成员列表 $\rightarrow$ 点击“小林”卡片的「编辑」进入独立编辑页 $\rightarrow$ 修改忌口或设置“肠胃不适”起止日期（验证结束日期早于开始日期时的红字阻断提示）$\rightarrow$ 点击「保存」返回列表看到绿色“进行中”更新结果。
4. **目标态链路四（识别核对至采购入库全链路）**：在标注“目标态 / 模拟数据”的前提下，演示「识别结果核对页」逐条确认候选食材 $\rightarrow$ 缺少食材加入「采购清单」$\rightarrow$ 标记为“已购买”$\rightarrow$ 独立进入「确认入库页」核对实际数量（2 盒）或标记“数量未知”并确认写入冰箱库存。

### 6.2 视觉与前端开发验收检查表
* [ ] **主导航合规性**：底部是否严格保持「冰箱 / 助手 / 采购 / 家庭」四栏，未增加第五个 Tab？
* [ ] **模块边界纯净度**：家庭板块是否已彻底剔除“我的冰箱”、设备状态与食材预览？
* [ ] **业务概念解耦**：采购板块中“已购买”与“已入库”是否已严格分开，入库是否有独立的实际数量/数量未知核对步骤？
* [ ] **过敏与忌口区分**：人员档案与晚餐建议中，医学过敏是否同时具备暗红警示色、`⚠️` 图标与“过敏”文字前缀，且未与普通饮食忌口混同？
* [ ] **窄屏与长文本适配**：在 360 px 窄屏宽度下，长食材名称、长家庭名称、确认时间戳与“数量未知”胶囊是否自然折行且无重叠截断？
* [ ] **真实性红线**：所有页面是否均未出现虚构的摄像头在线状态、实时抓拍照片、识别置信度百分比，且所有未开放接口的操作均已在画面内醒目标注“目标态 / 模拟数据”？
