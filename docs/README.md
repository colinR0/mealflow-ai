## 后续已确认决策

- 产品定位为某国产冰箱品牌高端旗舰冰箱的配套 App。冰箱内置摄像头，目标通过 YOLO 对画面中的食材画框标注，再由用户核对；当前设备与识别服务尚未接入。
- 用户可见名称暂用“智慧冰箱”，移除 MealFlow 品牌展示；内部工程名、协议标识保持兼容。
- 仅支持中国大陆 11 位手机号与密码登录，不提供邮箱登录。旧邮箱字段仅保留为历史数据；未关联手机号的旧账号不能用邮箱登录。
- App 入口统一验证登录态；未登录或会话过期进入独立登录页，登录后进入冰箱首页。网络故障保留本地会话并提供重试。
- 底部“家庭”改为“我的”：账号信息、人员信息、我的家庭、当前版本和退出登录。人员档案在二级页维护，用于助手判断用餐人员的饮食约束；“我的家庭”当前仅提供展示与邀请功能框架。
- 日常界面隐藏家庭选择；无关联家庭的账号自动创建个人空间，既有多家庭账号沿用上次选择的空间且不迁移旧数据。新建或接受第二个家庭由 API 拒绝；现有邀请码加入流程尚未对个人空间提供迁移方案。

- 只使用 PostgreSQL；旧数据不恢复，旧库和导入能力已清除。基线中的旧数据迁移要求已取消。
- 交付形态已调整为独立 Android App，采用 HBuilderX + uni-app + Vue 3 + TypeScript，页面使用 Options API。桌面基线中的首期移动网页决策已被此决定取代。
- 家庭端四入口为冰箱、助手、采购、家庭。品牌管理端独立，家庭端不沿用桌面三栏后台作为首页。
- 视觉模型和设备画面未接入，页面保留明确空态，不伪造识别结果。
- 品牌名称、Logo 与主题视觉尚未由客户提供，当前使用 MealFlow 通用标识。
- 家庭用户只有一个 `user` 角色，创建者和受邀者能力相同；邀请仍要求有效家庭成员关系，跨家庭访问和个人会话隔离继续校验。
- 移动 UI 采用浅蓝渐变、圆角白卡、冰箱示意主视觉和场景入口；加载骨架、按压反馈及任务运行动态支持减少动效偏好。示意冰箱不代表真实设备画面。
- 旧聊天入口缺少当前账号身份，不再推断主账号并自动保存长期偏好；本轮条件仍保留，长期偏好通过 v2 确认流程保存。

## 本批实现范围

- 移动四入口与公共视觉；冰箱画面/识别空态。
- 家庭账号登录、家庭选择、v2 已确认食材和采购清单读取。
- 冰箱库存列表支持服务端搜索、数量与在库/已用完/已移除状态筛选，以及匹配总数和分页加载；首页统计使用全量在库统计端点，预览最多载入 100 条。确认时间按本地时区展示。
- 助手已建立 uni-app 对话页，接持久化任务 API 和 App 分块请求；真机 SSE 断线恢复仍待设备验收。
- 助手 worker 已复用旧版默认模型配置（当前默认 GLM-4.5-Air），正常运行不再使用 FakeProvider；最近 10 轮成功或待补充/确认任务用于多轮上下文。模型缺少配置或调用失败会返回明确错误，不降级为模拟回复。启动 API 后仍需单独运行 `python -m app.worker`。H5 使用 fetch 读取 SSE，App 保留原生分块请求；菜谱/技能/结构化 RAG 已接入本轮检索约束；配餐策略不在本次接入范围。
- 助手采用连续消息布局，支持基础 Markdown、复制、停止、任务状态检查、采购/偏好确认与拒绝；V2 会话提供分页历史、继续对话和删除入口，按账号与家庭隔离。删除仅隐藏会话并禁止继续发送，保留任务与业务审计记录；执行中的会话需先停止。当前会话 ID 按账号与家庭保存在本机，刷新后从服务端恢复消息；token 预算与摘要压缩尚未实现。
- 移动端已支持手动登记、编辑数量与备注、确认用完和软移除；库存写入携带预期版本，冲突返回 409，终态不可重复或交叉转换。采购状态修改、入库、家庭管理与设备服务仍需配套接口及后续页面。
- 旧 Vue Web 管理端、工作台及桌面兼容入口已从 `apps/web` 替换；品牌管理端尚未建设。
- 新增三个独立结构化知识库：食材替换、风味模板、禁忌/风险分别建表，结构化字段与专用 `rag_text`/向量分离；检索先召回 ID/版本再读取结构化行，只有 `approved` 行进入回答。风味/风险种子当前为 `draft`，未作为正式比例或医学结论启用。
- 菜谱、技能和结构化知识支持本地 `sentence-transformers` 向量：固定 `BAAI/bge-small-zh-v1.5` 512 维，查询使用 BGE 中文检索前缀，provider/profile/维度不一致时拒绝检索。默认仍为 demo + fake 64；本地 `mealflow_rag` 已迁移到 512 维，并重建 462 个菜谱/技能文档（462 个 chunk）和本次导入的 16 行结构化知识。
