## 交付行为

- 统一 `RecipeRetriever.search(query, top_k=5, mode="hybrid")`，支持 vector / fts / hybrid；`search_all` 共用一次问题向量化和同一数据库快照展示三路结果。
- 复用 BGE small 中文版 512 维编码和 pgvector 查询，模型按实例延迟加载并复用；纯全文查询不访问模型目录或加载模型。
- 全文使用 jieba 与 PostgreSQL `simple` / `plainto_tsquery` / `ts_rank`，增加 `@@` 匹配和正分数过滤；不是 BM25。
- 各路先召回最多 160 个片段，保留最多 20 道去重父菜谱；RRF 等权、k=60，每道菜每路只贡献一次最好名次，默认返回 5 道。
- 返回来源、版本、原文片段、各路名次与原始分数、融合分数、批次与耗时；稳定处理同分排序。
- 先读取批次配置，事务外完成模型推理，再在只读可重复读事务中复核批次及召回；核对模型配置、当前父文档摘要、来源和片段内容版本。
- 区分输入错误、索引/模型/连接配置错误、向量化失败、数据库故障、证据错配和空召回；不静默降级。
- 单次查询增加 `--mode vector|fts|hybrid|all`，默认 all。原有问题集评估函数及其结果整理函数保留，不增加混合评估逻辑。
- 不修改业务表、索引内容、迁移、发布状态、问答生成入口、App 或 Agent。

## 已知缺口

- 全文查询为分词后 AND 匹配，长口语问题可能无候选；没有查询改写、同义词扩展或重排。
- 片段预算固定 160，父菜谱去重后不足 20 道不会继续补齐。
- 没有相关性不足判定、忌口硬过滤、配餐、详情接口或回答生成。
- 现有批次没有权重指纹；当前模型配置检查不证明权重与建库时逐字节相同。
- 现有父文档表不是按批次不可变快照；可阻止渲染正文改变后继续混用旧片段，但不能完全追溯仅来源元数据变化的历史。
- 同步实例的并发生命周期、推理限流、超时及线上性能仍待接入设计与验证。
- 全文过滤会改变未来评估结果，不能把旧报告当成本轮实现的质量结论；未宣称混合优于单路或达到正式接入标准。
