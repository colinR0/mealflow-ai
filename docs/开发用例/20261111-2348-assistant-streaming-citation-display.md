# 助手逐字显示、思考过程与菜谱溯源标签清理

- 日期：2026-11-11
- 用户确认：本次需要填写开发记录。
- 范围：助手最终回答的逐字显示、执行过程思考步骤、正文引用/来源标签清理，以及菜谱来源卡片隐藏。

## 问题与行为

1. 最终回答不再一次性整段出现。前端在收到 `completed` 结果后以 16ms/字符逐字显示；若本次回答首次出现思考步骤，先保留 450ms 展示思考过程，再开始回答。消息标题状态在渐显期间显示“正在回答”，正文末尾显示光标；提供“显示全文”立即完成渐显。复制始终使用完整正文，不复制光标或按钮文字。
2. 思考步骤来自后端真实执行 trace，不展示模型原始思维链。普通工具调用继续用已有工具步骤；固定忌口校验路径会显示“读取家庭档案、库存与已登记限制”“核对已登记的过敏原与忌口”等步骤。新回答默认展开，历史消息保存步骤但默认折叠，可手动展开。
3. 后端在校验和引用处理完成后清理最终正文：移除 `[recipe:…]`、`[knowledge:…]`、`[web:…]`、`[log:…]` 等内部标记，同时保留 `citations` 与 `evidence` 供校验和来源使用。清理只移除标记两侧的水平空白，保留菜谱步骤换行，避免把两行步骤粘成一行。
4. 标签被移除后留下的空“来源：”“参考来源：”“出处：”行会被删除；正文中仍有实际内容的来源行不主动改写。固定忌口/替代菜谱回答不再自行拼接 `[recipe:…]`。
5. 前端对旧历史消息再次执行同一套文本清理，避免升级前已保存的标签继续显示。菜谱和烹饪技能正文已经内联在回答中，因此不再渲染“菜谱来源”/“烹饪技能来源”卡片；网页、替换、风味模板和风险证据卡片继续保留。
6. 持久化 worker 目前仍只在任务结束时发出 `completed`，所以本次是客户端渐显，不是模型 token 级流式；已有 SSE `text_delta` 处理仍保留，未来后端发送增量时会继续追加而不是整段替换。
