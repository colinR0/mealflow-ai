# 忌口后的库存方向选择与菜谱展开

- 日期：2026-11-12
- 用户确认：本次需要填写开发记录。
- 范围：命中已登记过敏/忌口后的口味方向选项、active 库存依据与缺口、方向点选后的 1–2 道完整菜谱，以及助手页方向卡片。

## 问题与行为

1. 明确请求受限食材时仍先走确定性校验，不调用模型，也不直接倾倒完整菜谱。命中过敏或忌口后先返回最多 3 个方向：清淡蒸煮、酸辣开胃、红烧酱香、快炒下饭、汤羹暖胃；方向不足时用“家常推荐”兜底。方向只会读取菜名、分类、标签和口味标签，不把普通食材名当作口味依据，避免“番茄”把“红烧茄子”误判为酸辣。
2. 方向选项使用结构化 `result.options`，字段为 `key/label/example/recipe_id/reason/missing/prompt`，不新增独立 API。`prompt` 带本次登记限制和“方向”字样，点选后作为新一轮用户消息重新进入确定性忌口处理。
3. 库存只读取 `InventoryLot.status == "active"` 的记录。已知数量只作为“库存已有”依据；未知数量只追加“数量待核对”，不推断够几人份；库存为空时明确写“库存暂无可用记录”，不伪装成库存推荐。`missing` 列出菜谱中缺失的非可选食材。
4. 方向候选排除 `酱料`、`饮品` 两类非完整菜；“红烧酱香”不再用单独的“酱”匹配，避免把“金枪鱼酱三明治”算成红烧菜。选择方向后从已通过家庭限制校验的候选中按库存匹配数、方向匹配度、同类食材、食材数量和耗时排序，展开 1–2 道完整菜谱。选中方向没有候选时，重新返回其他方向选项，避免旧选项消失后无法继续。
5. 前端仅在最新一条回答、逐字渐显结束后展示方向卡片；点选立即发起新一轮，旧选项随新 run 失效。卡片显示方向、示例菜、库存依据/缺口和“只读推荐，不会改动库存或采购清单”。采购与偏好写入仍需原有确认流程。
6. 选项随 completed 结果和历史会话保存；刷新历史后仍可恢复，已选择方向的完整菜谱不会重新出现旧选项。正文继续走原有清理，不显示 `[recipe:…]`、空“来源：”或菜谱来源卡片。
