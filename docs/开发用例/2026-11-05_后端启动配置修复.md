# 后端启动配置修复记录

日期：2026-11-05

## 问题

PyCharm 的 `MealFlow API` 运行配置指向仓库 `.venv/Scripts/python.exe`，该环境缺少 FastAPI 和 uvicorn，IDE 提示找不到运行配置的 Python 解释器。开发数据库 `mealflow_s7` 也落后于当前 Alembic head，API 启动保护会拒绝启动。

## 处理

- 将 `.idea/runConfigurations/MealFlow_API.xml` 的解释器改为 `D:/APP/miniconda3/envs/mealflow/python.exe`，并使用现有 SDK 名称 `mealflow`。
- 在执行迁移前确认根目录 `.env` 的 `DATABASE_URL` 指向 `mealflow_s7`，并核对当前版本 `3c6d8e0f1a2b`、唯一 head `f1a2b3c4d5e6`。
- 使用 Conda `mealflow` 环境执行 `alembic upgrade head`，迁移成功应用 `f1a2b3c4d5e6_inventory_lot_lifecycle`。
- 更新 `AGENTS.md` 的 Windows Python 命令与 IDE 解释器路径，并新增 Agent1 开发 -> Agent2 测试 -> Agent1 按测试记录修复一次 -> 停止的固定流程约束。

## 验证

- Conda Python 3.12.12 可导入 FastAPI 和 uvicorn。
- 迁移命令成功执行：`3c6d8e0f1a2b -> f1a2b3c4d5e6`。
- 迁移后 `alembic current` 与 `alembic heads` 均为 `f1a2b3c4d5e6 (head)`。
- 8000 端口已有本项目 Conda 环境启动的 API；启动保护通过，`GET /api/v1/health` 返回 `status: ok`。`/health` 不是本项目的健康检查路径，返回 404 属预期。
