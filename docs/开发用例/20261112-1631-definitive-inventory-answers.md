# 库存有无改为确定性回答

- 日期：2026-11-12 16:31
- 范围：`apps/api/app/agent/durable_graph.py`、`apps/api/tests/test_durable_graph.py`、`docs/README.md`
- 状态：已实现并通过自动化测试；未提交；未做 H5 手动点击和 Android 真机回归

## 问题与根因

- 用户问“冰箱里还有鸡蛋吗？”，助手回答“没有查到鸡蛋的库存记录……所以目前无法确认……也不能据此断定没有”，结论模棱两可。
- 根因是 `BASE_SYSTEM_PROMPT` 里明确要求“没有库存记录只能说明未查到，不能断言冰箱里没有该食材”。模型忠实执行了这条约束，把“库存记录里没有”说成了“无法确认”。
- 该问题只靠提示词约束并不可靠，库存存在性问题需要一个服务端确定性回答路径。

## 本次决策

- 库存有无以本轮 `active` 库存记录为唯一依据：
  - 有匹配记录且数量未知 → “有，数量待核对”；
  - 有匹配记录且已知数量大于 0 → “有”并给数量；
  - 没有匹配记录，或已知数量为 0 → “没有”。
- 直接存在性提问（“还有 X 吗”“有没有 X”“X 还有吗”）走服务端确定性路径，不经过模型措辞。
- “够不够、缺什么、能不能做、怎么做、推荐”等需要比较或烹饪知识的问题继续走模型路径；提示词同步禁止“无法确认/不能断言/可能没有”等模糊说法。
- 回答限定在库存记录范围，不把“库存里没有”扩展成对家庭物理存量的绝对判断。

## 修改内容

- `BASE_SYSTEM_PROMPT`：删除“没有库存记录……不能断言冰箱里没有该食材”，改为按 `active` 库存记录明确回答有/没有，数量未知说明待核对，并禁止模糊措辞。
- 新增 `is_inventory_question()` 与 `inventory_question_names()`：
  - 只识别存在性问句，排除“怎么做、做法、菜谱、推荐、够不够、缺什么、能做、做什么、好吃”等意图；
  - 食材名从上下文 `ingredient_names` 和当前 active 库存名称中做最长匹配，避免“蛋”覆盖“鸡蛋”、“油”覆盖“酱油”。
- 新增 `Runtime.inventory_existence_request()`：
  - 命中存在性问句后直接查询家庭 active 库存；
  - 按食材名/目录 key 匹配库存；已知数量为 0 视为没有；
  - 输出“有。鸡蛋 6个。”、“有。鸡蛋的数量待核对。”或“没有。当前库存没有鸡蛋。”；
  - 附带库存证据 ID，保持可追溯；不调用模型、不产生模型预算消耗。
- `decide()` 在忌口与点名菜确定性路径之后、模型调用之前接入该路径。
- 新增测试：有记录、无记录、数量未知、已知 0、问句识别排除其他意图、提示词禁止模糊措辞。

## 行为变化

- “冰箱里还有鸡蛋吗？”在库存有记录时直接回答“有”并给出数量；无记录或数量为 0 时直接回答“没有”。
- 数量未知的库存回答“有，数量待核对”，不再说“无法确认有没有”。
- 不再出现“只查到其他食材，所以无法确认”这类因检索结果不完整而模糊的结论。
- “鸡蛋够不够做蛋糕”“冰箱里有什么”“鸡蛋怎么做”等问题不受影响，仍走原有模型/工具路径。
