# MealFlow —— 面向家庭厨房的智能配餐 Agent

> 一句话介绍：**对着对话框说"明天中午两个人吃，想吃辣子鸡，预算 60 块"，AI 会先查家里人的忌口和身体状况，再看看冰箱里有什么，然后给你一份能说清楚"为什么这么配、花多少钱"的菜单、食谱和采购清单——全过程直播，且安全约束不靠 AI 自觉，靠确定性代码保证。**

本文面向想了解这个项目的朋友：前半部分讲"它是什么、能干什么"，后半部分讲"怎么实现的、代码在哪"。欢迎对照代码阅读。

---

## 1. 它解决什么问题？

每个小家庭都遇到过这些日常难题：

- 冰箱里一堆食材，不知道怎么搭配着吃掉，临期的总是忘；
- 家里有人感冒、有人例假、有人过敏，每次做饭都要在脑子里过一遍"这个能不能吃"；
- 网上查菜谱，量不对（按 4 人份写的，你家 2 个人）、成本不清楚；
- 通用 AI 聊天机器人嘴上答应得很好，一转身上下文就忘了你爱人对虾过敏。

MealFlow 的答案：**把"配餐"做成一个受控的 Agent 系统**——大模型负责理解意图、组织语言，而真正决定"做什么菜"的是一圈确定性代码工具。它不是又一个"套壳聊天机器人"，核心卖点恰恰是**让 LLM 干活，但不让它越权**。

项目 2026 年 9 月以政务食堂为背景立项（V1），10 月初完成 V2 定稿，**把家庭厨房确立为唯一主线**，删除了政务场景代码，全面转向对话式 Agent 工作台。

## 2. 核心使用流程（一段真实交互）

```
你：明天中午两个人吃，想吃辣子鸡，预算 60 块。

Agent（思考区，小字直播）：正在检查用餐限制……
Agent（工具步骤，逐条打勾）：
  ✔ 检查用餐限制 —— 发现：成员A 感冒中（忌辛辣油腻），成员B 例假期（忌辛辣生冷、香菜、虾过敏）
  ✔ 读取冰箱库存 —— 鸡腿肉、干辣椒、花生米…… 14 项可用
  ✔ 检索菜谱库 —— 937 道菜谱中命中 3 道
  ✔ 估算成本 —— 按市区大型超市公开参考价
Agent（逐字输出 + 方案卡）：
  ⚠️ 辣子鸡你点名了，我照常给出做法，但两位今天的身体状况都不适合吃辣，
     不建议做。给你一版改良建议 + 2 个替代主菜……
  [方案卡] 菜单 / 按人数换算的食谱 / 冰箱食材消耗量 / 参考价与预算差额
  [快捷追问] "换成不辣的" "只看 A 能吃的" "加入采购清单"
```

三条产品铁律贯穿全程（出自 `docs/V2改造方案-对话式Agent工作台.md`）：

1. **约束前置**：忌口、过敏、带生效日期的特殊事件（感冒、例假……到期自动失效）先于一切注入，每轮先"检查用餐限制"；
2. **库存优先**：冰箱食材是第一输入，方案最大化消耗现有食材，临期优先；
3. **点名菜不硬拒**：想吃辣子鸡照常给菜单和食谱，但与忌口冲突时明确警示"不建议做" + 原因 + 替代建议——尊重选择权，但不装作没看见风险；
4. **物价可溯源**：所有金额挂"市区大型超市公开参考价"来源标注，不编造实时报价；
5. **预算是软约束**：超支要讲清差多少、差在哪个食材。

## 3. 功能全景

侧边栏七入口（`apps/web/src/layouts/AdminLayout.vue`）：

| 模块 | 说明 |
|---|---|
| **智能配餐**（核心） | 对话工作台：SSE 流式对话、本次用餐人员多选、多模型切换、方案卡、会话历史 |
| **冰箱库存** | 食材 CRUD、搜索分类、临期提醒 |
| **采购清单** | 家庭共享采购清单，方案一键加入 |
| **下厨足迹** | 做过的菜、评分、记录，形成反馈 |
| **人员信息** | 家庭成员、忌口/过敏、特殊事件（带生效日期）、长期偏好、常备料配置 |
| **懒人宝典** | 937 道清洗合并的外部菜谱库（下厨房/HowToCook 等），可按食材找菜、一键"交给 Agent" |
| **代码练兵场** | 6 关前端学习工作台，借本项目学 Function Calling 开发 |

### 技术栈

- **后端**：Python 3.12/3.13 · FastAPI · SQLAlchemy 2 · Alembic · LangGraph · OpenAI SDK（兼容协议）· Pydantic v2 · pytest（19 个测试文件、103 个用例）
- **前端**：Vue 3.5 · TypeScript 5.7 · Vite 6 · Element Plus 2.14 · Pinia 3 · vue-router 4
- **数据**：PostgreSQL；种子菜谱 32 道 + 外部菜谱库 937 道
- **部署**：本地 venv / Docker Compose / 局域网双人开发脚本（`scripts/start-*-lan.ps1`）

## 5. 最值得看的三个亮点

### ① "步骤直播"——全透明的 Agent

从输入一句话到出方案，思考小字、每个工具调用逐条打勾、正文逐字输出，全部实时可见（SSE 五阶段消息生命周期：思考 → 工具步骤 → 逐字回答 → 方案卡 → 快捷追问）。而且工具轨迹会持久化到 `tool_traces` 表，事后可回看。**AI 不是黑盒，每一步都有据可查。**

### ② 安全约束是确定性代码，不是提示词承诺

这是本项目和"套壳应用"的本质区别：

- **过敏原硬过滤**（`apps/api/app/services/planning.py` 的 `hard_filter()`）：命中过敏原的菜谱直接从候选剔除，普通忌口则保留但加警示——这是代码逻辑，模型想绕也绕不过；
- **协议护栏**（`apps/api/app/llm/protocol_guard.py`）：模型偶尔会把工具调用信封误写进正文，护栏负责还原/拦截，流式场景用 64 字符缓冲窗口防止半截标记漏出；
- **降级链**：拔掉 API Key，系统自动落到确定性规则基线，照样出带约束检查的方案——**模型全挂，安全不挂**。

### ③ "受控补齐"——让模型生成内容，但关进笼子

本地 937 道菜谱凑不齐一餐时，允许模型现场生成缺失的菜谱，但有严格牢笼：最多补 2 道、只允许重排一次（防无限递归）、必须通过 Pydantic 结构校验 + 禁忌食材安全校验、前端明确标注"模型生成做法"、只进内存上下文不写数据库。配合"所有金额挂公开参考价来源"，完整展示了 **LLM 边界设计**的工程范式。

## 8. 怎么跑起来

环境要求：Python 3.12/3.13、Node.js 20+。

```bash
# 后端
python -m venv .venv
pip install -e "apps/api[dev]"
copy .env.example .env        # 填入至少一个模型 API Key（默认智谱 GLM）
cd apps/api
..\..\.venv\Scripts\python.exe -m alembic upgrade head
..\..\.venv\Scripts\python.exe -m app.db.seed      # 灌入演示家庭 + 菜谱
..\..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

# 前端（另开终端）
cd apps/web
npm ci
npm run dev
```

打开 http://localhost:5173/admin/agent 即可对话；接口文档在 http://localhost:8000/docs 。
没有 Key 也能跑——系统会自动降级到确定性规则基线（这本身就是一个演示点）。

验证命令：`pytest apps/api -q`（后端）、`npm run typecheck && npm run build`（前端）。
